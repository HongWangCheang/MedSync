# 端侧路由评测

把用户的一句中文变成要执行的动作（记录服药 / 记录症状 / 预约 / 通知家属 / 药学问答）。比较两个路由器：

- **rules**：原来的规则路由（`RuleRouter`），离线、零延迟，作为基线
- **qwen3-0.6b**：Qwen3-0.6B int4（litert-community，Apache-2.0，328 MB），通过 LiteRT-LM 0.19.1 在设备上运行，用工具调用（tool calling）输出动作

## 结果

| | rules | qwen3-0.6b |
|---|---|---|
| test：整句完全正确 | 48% | **87%** |
| test：工具选择正确 | 58% | **91%** |
| dev：整句完全正确 | 53% | 93% |
| 延迟 p50 / p95 | < 0.1 ms | 2.0 s / 4.1 s |

逐项指标、按类别的结果和错例见 [REPORT.md](REPORT.md)。

## 怎么测的

- **评测集**：`utterances.jsonl`，210 句，由 [build_set.py](build_set.py) 生成，标签可以直接审阅。覆盖单药、多药、否定、症状、预约、通知、复合句、提问，以及一批陷阱（"吃了头孢能喝酒吗"是提问，不是服药记录；"告诉爸爸明天去复诊"是通知，不是预约）。标签按"细心的助手应该怎么做"来写，不是按规则的输出写。
- **dev / test**：每类里 3/5 作 dev（131 句），2/5 作 test（79 句）。提示词和代码护栏只看 dev 调；test 只在最后跑一次。
- **打分**：[score.py](score.py)。药名对数量和剂型宽松（"两片泰诺"算泰诺），同义词归一（头疼 = 头痛、心内科 = 心血管内科）；科室和日期只在用户说了的时候才检查。
- **测试机**：Apple M4 Pro，24 GB，macOS 26.5.1，CPU 后端。**没有真机**：用 LiteRT-LM 的 JVM 运行时在 Mac 上代替手机，Kotlin API 和 Android 版相同，但手机上的延迟需要另测。

```sh
cd client && MEDSYNC_ROUTING_EVAL=1 ./gradlew --no-configuration-cache :desktopApp:test --tests '*RoutingEvalTest*'
python3 eval/routing/score.py
```

（模型文件放在 `~/.medsync/models/Qwen3-0.6B_dynamic_wi4b32_afp32.litertlm`，或用 `MEDSYNC_MODEL` 指定。）

## 模型负责什么，代码负责什么

0.6B 模型只负责"理解"：这句话要做哪几件事、提到了哪个药。小模型不擅长的部分交给确定性的代码（`client/shared/.../agents/ModelPlan.kt`，各平台共用）：

1. **按分句路由**：陈述句按逗号拆开，每个分句单独问模型，再合并。0.6B 一次稳定地只给一两个工具调用，复合句（4 个动作）整句问时一个都对不全；提问句整句问。
2. **日期由代码解析**：从用户原话里算日期，模型不做日期换算。
3. **参数必须出现在原话里**：药名、症状、家属、科室都要能在用户的话里找到，否则丢弃（科室改由规则推断），不猜。
4. **否定**："还没吃降压药"不记录，"没有头疼"不算症状。
5. **提问优先**：一句话在提问、又没要求预约或通知时，只交给药学 Agent，不记录服药。
6. **家属称谓从原话里读**：模型会照抄提示词示例里的"老伴"，而称谓是封闭词表，直接从原话找更可靠。

模型不可用、超时（10 秒）或出错时，自动退回规则路由（`FallbackRouter`），保证离线时总能给出计划。

## 需要如实说明的

- **dev 上调过**：上面的护栏都是看了 dev 的错例之后加的；test 没有参与调参。dev 从第一版的 74% 提到 93%，test 是 87%。
- **两次运行之间有 ±2 个点的波动**：同样的代码 dev 跑出过 91% 和 93%，贪心解码在 CPU 上也不完全确定。
- **test 上发现的 3 个 bug，修了但没有重跑**：跑完 test 后看错例，发现"约一下周二"被当成下周二（规则路由也有这个 bug）、"我妈"被归一成"妈"、"有没有"没算作提问。已修复并加了单测，但为了不让 test 变成调参集，上表仍是修复前的数字。
- **标签是我写的**：评测集和规则路由都出自同一个人，可能有偏差；欢迎补充新句子。
- **延迟是 Mac CPU 上的数字**：第一次加载模型约 7 秒（App 启动时在后台预热）；手机 CPU 会更慢。
