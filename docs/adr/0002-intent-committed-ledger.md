# 0002 executor 双阶段记账：INTENT → COMMITTED

状态：已采用

## 背景

调用外部系统时，最难处理的是"请求发出去了，响应没回来"。对方可能已经执行了，也可能没有。直接重试会重复预约，直接放弃会漏掉动作。

## 决定

`tool_ledger`（Postgres）每个 step_key 一行：
1. 调用前写 `INTENT`，带一个租约。
2. 调用成功后改成 `COMMITTED`，同时存下结果。
3. 再次执行同一步时：
   - `COMMITTED`：直接返回存下的结果，不再调用外部系统。
   - `INTENT` 且租约有效：说明另一个 worker 正在调用，这次只返回"等待中"，网关之后再问。
   - `INTENT` 且租约过期：结果不明，**先按 step_key 去外部系统查**；查到就补记 COMMITTED，查不到才重新调用。
   - 外部系统明确拒绝：释放这一行，允许之后重试。

## 后果

- "已提交、响应丢失"不会变成重复副作用。
- 依赖外部系统提供按 step_key 查询，或者接受幂等键。
- 外部系统不可达时，动作停在 INTENT，状态为"等待中"，之后再试；不会把"不知道"当成"失败"。
