# 0007 跨 Agent 冲突：发现板 + 不可逆动作前检查

状态：已采用

## 背景

离线时，手机按当时的理解排好了动作，例如"吃了布洛芬，告诉女儿我没事"。联网后，安全审核发现布洛芬和之前记录的华法林有出血风险。排队的"我没事"已经和事实矛盾了，但发消息的 Agent 并不知道这个结论。

## 决定

- 安全审核和药学 Agent 把结论写到"发现板"（Postgres 表 `agent_finding`），彼此不直接调用。
- 不可逆的动作执行前，查有没有"规划时还不知道"的结论。规则写在 `conflicts.py`，故意很少：
  - 通知家属 + 高风险提醒 → 暂停
  - 通知家属 + 一般提醒 + 消息里有"没事""放心"之类的话 → 暂停
  - 预约 → 不暂停（去看医生和提醒并不矛盾）
- 暂停时给三个选项："附上提醒再发 / 照原样发 / 取消"。附上的文字由服务器根据审核结果生成，不采用手机传回的内容。
- 同一句话里，通知依赖服药记录（DAG），所以审核结论一定先写到发现板。

## 后果

- Agent 之间通过数据协作，不互相调用，任何一个 Agent 挂了都不会拖住别的 Agent。
- 规则少，有些矛盾会漏掉，例如消息内容和结论间接相关。这是为了让每次暂停都说得清理由。
